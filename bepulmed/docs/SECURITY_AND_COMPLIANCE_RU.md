# BepulMed AI 2.8 — безопасность и юридическая готовность (RU)

## Важно: это технические меры, не юридическое заключение

Перед запуском с реальными пациентами необходимы письменная проверка юриста Узбекистана,
определение владельца/оператора базы, основания обработки, согласия, сроки хранения,
процедуры доступа/исправления/удаления, договоры с обработчиками и оценка трансграничной передачи.

## Закон о персональных данных

Проверена редакция Закона № ЗРУ-547 на LexUZ в состоянии на 27.03.2026.
Статья 25 относит сведения о физическом и психическом здоровье к специальным персональным данным.
Статья 27¹ в редакции Закона № ЗРУ-1125 от 26.03.2026 устанавливает обязательное хранение
в Узбекистане для биометрических, генетических данных и данных пользователей телеком-операторов.
Иные персональные данные могут обрабатываться за рубежом только при выполнении предусмотренных
законом условий трансграничной передачи. Это не означает, что медицинские данные можно свободно
отправлять зарубежному ИИ: отдельно применяются требования к специальным данным (ст. 25),
согласию, конфиденциальности, целям и поручению обработки (ст. 21, 22, 23, 25, 28, 31).

Официальный источник: https://lex.uz/ru/acts/4396428?ONDATE=27.03.2026+00
Перевод LexUZ помечает часть редакции 2026 года как неофициальную; юрист должен сверить официальный
узбекский текст Закона № ЗРУ-1125 и подзаконные акты до ввода в эксплуатацию.

## Что включено в коде как безопасное значение по умолчанию

- `PATIENT_DATA_HOST_APPROVED = "false"`: все API записи/очереди/кабинета клиники блокируются.
- `SERVER_HEALTH_CHAT_ENABLED = "false"`: приложение отвечает на медицинские вопросы локально; Worker не принимает историю симптомов.
  Включать можно только после подтверждения площадки размещения в Узбекистане, защиты и правовой проверки.
- `EXTERNAL_AI_TRANSFER_APPROVED = "false"`: медицинский чат работает по локальной базе источников;
  пользовательские сообщения не отправляются в Gemini/VoiceLab.
- `EXTERNAL_VOICE_TRANSFER_APPROVED = "false"`: аудио/текст не отправляются во внешний STT/TTS.
- Экстренный триаж и чат по встроенной базе выполняются прямо на устройстве; приложение не отправляет историю симптомов на Worker.
- Распознавание речи (Android и iOS) — по умолчанию только на устройстве; через Google/Apple — только после явного согласия в приложении (можно отозвать на экране «Защита данных»); Web Speech API в браузере не включён, если офлайн-движок недоступен, голосовой ввод отключается.
- `MedicalScanner.tsx` использует локальный OCR и не отправляет фотографию в API BepulMed.
- `Medicines.tsx` — справочный каталог; не должен назначать лечение или дозировки.
- Медкарта SOS хранится на устройстве; не синхронизировать её в облако без отдельного правового основания.

## Архитектура production

1. Разместить backend и основную БД на площадке в Узбекистане (договор с провайдером,
   подтверждение физической локации, резервных копий, журналов, мониторинга и субподрядчиков).
2. Использовать PostgreSQL с TLS, шифрованием дисков/backup, ротацией секретов, RBAC,
   MFA для сотрудников, аудитом чтения/изменения, минимизацией и сроками удаления.
3. Не использовать Cloudflare D1 как хранилище пациентов. CDN/WAF можно оценивать отдельно,
   но исключить из его логов тела запросов, ПИНФЛ, медицинские данные и токены.
4. Не передавать запросы, аудио, фото рецептов, анализы, медкарту или ПИНФЛ Gemini/VoiceLab.
   Внешний ИИ не включать флагом без отдельного письменного согласия, договора обработки,
   оценки трансграничной передачи и проверки допустимости специальных персональных данных.
5. Разделить публичный каталог учреждений (без пациентских данных) и закрытый медицинский контур.

## DMED и ПИНФЛ (2.8)

Подключение сделано по опубликованному руководству Uzinfocom/Минздрава «Цифровая платформа
здравоохранения» (FHIR, раздел API access): FHIR `playground.dhp.uz/fhir` (тест) и `fhir.dhp.uz`
(боевой), вход OAuth 2.0 через `sso.dhp.uz`. Подробно — `docs/DMED_INTEGRATION_RU.md`.

- Выключено, пока Uzinfocom не выдал приложению `client_id` (переменная сборки `VITE_DMED_CLIENT_ID`).
- Вход — authorization code + PKCE (S256), без client_secret в приложении; проверка `state`,
  срок 10 минут, одноразовость. Возврат — `uz.bepulmed.app:/oauth2redirect` (RFC 8252):
  Android — системный браузер, iOS — `ASWebAuthenticationSession` (эфемерная сессия).
- Только чтение: пациент, поликлиника прикрепления, электронные рецепты, записи.
- Перед входом — экран согласия. Токен и данные — только в памяти телефона: не пишутся в хранилище,
  не уходят на сервер BepulMed и во внешний ИИ; «Выйти» удаляет сразу.
- Запросы — только к `*.dhp.uz` / `*.medcore.uz` по https (проверка в вебе, Android и iOS).
- ПИНФЛ приложение не спрашивает и не хранит: личность подтверждает SSO DMED.

## Каталог клиник

- `tashkentFacilities.ts` — автономный справочник; источники имеют разный уровень надёжности.
- `verifiedFacilities.ts` пустой намеренно: нельзя показывать значок «Проверено» без первичного
  подтверждения учреждением/Минздравом.
- OSM/Overpass — вспомогательный источник, не государственный реестр. Телефоны и часы могут
  отсутствовать/устаревать; данные показываются как непроверенные.
- Для production нужен редакторский процесс: источник, дата подтверждения, подтверждающий сотрудник,
  телефонный callback/официальная страница, статус актуальности и журнал изменений.

## Как включать локальный тест

Для локального тестового окружения разрешение можно включить только в `.dev.vars`:
`PATIENT_DATA_HOST_APPROVED=true`. Не переносить это значение в Cloudflare production.
Внешний ИИ и голос остаются выключенными. Это не превращает Cloudflare D1 в локальную базу Узбекистана.

## Что осталось до production

- Поднять отдельный backend/БД в Узбекистане и перенести туда booking/staff/waitlist API.
- Получить DMED API access и согласовать сценарии ПИНФЛ/прикрепления.
- Пройти аудит безопасности и юридическую проверку.
- Верифицировать каталог клиник и скорой помощи с официальными источниками.
- Провести клиническую экспертизу всех инструкций первой помощи (RU/UZ), включая педиатрию и беременность.
- Провести сборку APK, тесты на реальных устройствах и тестирование аварийных сценариев.

## Веб-защита (2.8)

- Content-Security-Policy в `index.html` (при сборке): скрипты только свои и SDK Telegram,
  WASM для локального OCR, без eval, плагинов и фреймов; `referrer: no-referrer`.
  Проверено: OCR и карта работают, нарушений CSP нет.
- Статика (`public/_headers`): nosniff, HSTS, no-referrer, Permissions-Policy, встраивание — только Telegram Web.
- API: no-store, nosniff, no-referrer, HSTS, `frame-ancestors 'none'` (тест в worker).
- Android: только HTTPS (кроме эмулятора/localhost), `allowBackup=false`, без file://, мост — только своей странице.
- iOS: мост принимает сообщения только от `bepulmed://app` в главном фрейме; запросы DMED — `URLSession.ephemeral`.

## Данные на устройстве

Медкарта SOS, последний список талонов (для офлайна), согласие на сетевое распознавание, кэш карты и
данных Ташкента — в хранилище приложения на телефоне. На экране «Защита данных» можно удалить
сохранённые талоны и отозвать согласие. Шифрования хранилища поверх системного нет — для production
рассмотреть Android Keystore / iOS Keychain для медкарты.

## Экран «Защита данных»

Меню → 🔒: показывает действующие меры на телефоне и флаги сервера из `/api/health`
(хранение пациентских данных, серверный чат, внешний ИИ, внешний голос).

## Онлайн-справка: аптеки, клиники, часы, рейтинг (2.9)

Цель — брать общедоступные данные из интернета, ничего не отправляя о человеке.

- «Открыто сейчас», часы, платно/бесплатно — из данных OpenStreetMap, сохранённых на телефоне;
  считаются на устройстве, работают без интернета. В Ташкенте карта «рядом» больше не отправляет
  местоположение на сервер; вне Ташкента координаты округляются до ~1 км.
- Рейтинг, число отзывов, расписание — 2GIS Places API (официальный) через сервер BepulMed;
  ключ `DGIS_KEY` только на сервере. Наружу уходит только тип, название учреждения и район
  (центр района, не местоположение). Запрос проверяется на телефоне и на сервере (`publicQuery.ts`):
  слова о человеке и состоянии («у меня», «болит», «ребёнок», возраст…), телефоны, ПИНФЛ, почта,
  ссылки — запрос не отправляется. Ответы кэшируются на сервере 6 ч, текст запроса не логируется.
- Тексты отзывов 2GIS — отдельное платное разрешение; показываются рейтинг, число отзывов и ссылка на 2GIS.
- Лекарства: ссылки на официальный pharm.gov.uz (референтные цены) и liki.uz — открываются
  в браузере по нажатию человека, BepulMed туда ничего не передаёт.
- Подложка карты (tile.openstreetmap.org) по своей природе видит, какой район просматривается.

## Офлайн-карта и автообновление (2.10)
- Карта Ташкента и снимок аптек/клиник встроены в приложение: просмотр карты и поиск рядом не отправляют
  местоположение никуда. Навигация — по GPS на телефоне.
- Автообновление скачивает общедоступные данные OSM целиком по Ташкенту (без координат пользователя).
- Лицензия карты и данных: ODbL, указание «© OpenStreetMap» отображается на карте.
