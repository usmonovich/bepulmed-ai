# BepulMed AI 2.6 — запись к врачу, прозрачная очередь и ИИ-навигатор (Telegram Mini App)

**Умная очередь. Доступная медицина. Никаких лишних поездок.**

> **Режим безопасности 2.6:** реальные пациентские данные не должны храниться в Cloudflare D1.
> API записи/очереди заблокирован по умолчанию (`PATIENT_DATA_HOST_APPROVED=false`).
> Gemini и внешний VoiceLab также выключены для медицинского чата/аудио по умолчанию.
> См. `docs/SECURITY_AND_COMPLIANCE_RU.md`. Cloudflare-конфигурация в этом архиве предназначена
> для демо/разработки до переноса backend и БД на согласованную площадку в Узбекистане.


BepulMed AI не заменяет DMED. Это доступный через Telegram интерфейс для пациентов и модуль управления очередью для подключённых клиник. Интеграция с DMED возможна в будущем, по соглашению.

## Архитектура

```
Telegram Mini App (React + TS)  ──►  Cloudflare Worker (TypeScript API)  ──►  D1 (SQLite): clinics, doctors, slots,
   пациент: чат, карта, запись,        проверка Telegram initData,                appointments, queue_events,
   талоны · #/admin: регистратура       права, запись, очередь, журнал              clinic_staff, audit_logs
                                      ├─► Внешний Gemini / VoiceLab (выключены по умолчанию; только после отдельного согласования)
                                      └─► OpenStreetMap Overpass (только публичный справочник; GPS-запросы — без пациентской БД)
```
Принцип: ИИ возвращает **намерение** (`find_doctor`, `cardiology`). Свободное время показывает база, а запись создаётся только после того, как пациент нажмёт «Подтвердить».

## Локальный запуск

```bash
cd web && npm install && npm run build
cd ../worker && npm install
npx wrangler d1 migrations apply bepulmed --local          # схема + демо-клиника
node scripts/create-staff.mjs --clinic demo-clinic --role registrar --name "Регистратор" >  staff.sql
node scripts/create-staff.mjs --clinic demo-clinic --role doctor --doctor doc-cardio --name "Кардиолог" >> staff.sql
node scripts/create-staff.mjs --clinic demo-clinic --role admin --name "Администратор" >> staff.sql
npx wrangler d1 execute bepulmed --local --file staff.sql  # токены печатаются один раз — сохраните
npx wrangler dev                                           # http://localhost:8787 и http://localhost:8787/#/admin
```
Необязательный файл `worker/.dev.vars`:
```
GEMINI_API_KEY=...
VOICELAB_API_KEY=vlk_...
```
Без ключей всё основное работает: запись, очередь, кабинет. Чат отвечает из базы источников, микрофон скрыт.

Тесты: `cd worker && npm test` (117 тестов, из них 32 на настоящем локальном D1); `cd web && npm test && npm run build`.

## Деплой (бесплатный тариф Cloudflare)

```bash
cd worker
npx wrangler login
npx wrangler d1 create bepulmed            # вставьте database_id в wrangler.toml
npx wrangler d1 migrations apply bepulmed --remote
npx wrangler d1 execute bepulmed --remote --file staff.sql   # новые токены для боевой БД!
npx wrangler secret put BOT_TOKEN
# Gemini / VoiceLab не включать для медицинских данных без отдельного правового основания.
# Секреты ниже нужны только для изолированного теста; маршруты внешнего ИИ/голоса закрыты по умолчанию.
npx wrangler secret put VOICELAB_API_KEY
npx wrangler secret put TG_WEBHOOK_SECRET
cd ../web && npm run build && cd ../worker && npx wrangler deploy
```
Затем:
1. В @BotFather укажите кнопку меню с URL приложения.
2. В `wrangler.toml` пропишите `WEBAPP_URL`.
3. Когда проверите работу в Telegram, поставьте `REQUIRE_TELEGRAM = "true"` и выполните `npx wrangler deploy` ещё раз.

С этой настройкой вход без Telegram отключён, работает только подписанный `initData`. Демо-пациенты в браузере тоже перестают работать.

**VoiceLab.** Ключ `vlk_…` должен иметь права `stt:write`, `tts:write`, а для LLM ещё `llm:access`. Чтобы чат отвечал через LLM VoiceLab, задайте `LLM_PROVIDER="voicelab"` и `VOICELAB_LLM_MODEL` — id модели можно получить так:
```bash
curl https://api.voicelab.uz/v1/models -H "Authorization: Bearer $VOICELAB_API_KEY"
```
Голос подбирается автоматически через `GET /v1/voices?language=…`. Конкретный голос можно закрепить переменными `VOICELAB_VOICE_UZ` и `VOICELAB_VOICE_RU`.

## Сценарий демонстрации для жюри (около 3 минут)

1. **Телефон (Telegram):** нажать 🎤 и сказать «Menga kardiolog kerak, можно записаться?». Приложение показывает распознанный текст, затем ответ ИИ и кнопку «Посмотреть свободное время — Кардиолог».
2. Выбрать завтрашнюю дату и время, нажать «Подтвердить». Появляется талон **K-00X**.
3. **Ноутбук `#/admin` (регистратор):** запись уже в расписании (обновление каждые 5 секунд). Нажать «Пришёл», затем «Вызвать».
4. **Телефон:** вкладка «Талоны» показывает «🔔 Вас вызывают! Подойдите к кабинету 205».
5. **Второй телефон:** открыть то же время до того, как первый пациент подтвердит запись. Нажать «Подтвердить» после него — появится «Это время только что заняли» и три ближайших свободных варианта.
6. **Ноутбук (администратор):** вкладка «Журнал» показывает, кто и что менял. Отмена записи без причины невозможна.
7. **Лист ожидания:** заполните день кардиолога через «+ записать» (или выберите день, где всё занято). Телефон: «Встать в лист ожидания» → «Место: 1». Ноутбук: отменить любую запись с причиной. Через ≤5 с на телефоне во вкладке «Талоны»: «🔔 Освободилось время! Удержано до …» с обратным отсчётом → «Записаться на это время». В кабинете слот помечен «⏳ удержано для пациента из листа ожидания».
8. **QR:** телефон показывает талон с QR. Ноутбук (регистратор): «📷 QR» → поднести телефон к камере → «✅ T-0XX … отмечен «Пришёл»». Без камеры — ввести код под QR вручную.
9. Резервный сценарий без интернета-голоса: всё то же самое текстом. Запись от ИИ не зависит.

## Ответы на вопросы менторов (со ссылкой на код)

- **Двойная запись?** Уникальный частичный индекс `one_active_booking_per_slot`. Проверено тестом: 10 одновременных запросов на один слот → 1×201 и 9×409.
- **ИИ отключился?** Запись, очередь и кабинет работают без ИИ. Чат отвечает из базы источников.
- **Смешанная речь?** Язык распознавания `auto`. Текст обязательно показывается пациенту до отправки, а перед записью приложение повторяет врача, дату и время.
- **Коррупционный обход очереди?** У каждой роли свои права. Каждое изменение записывается в журнал вместе с изменением статуса, одной транзакцией. Журнал защищён от изменений триггерами. Конкурентные правки ловятся проверкой `WHERE status = <прежний>`.
- **Пациенты без смартфона?** Регистратор записывает их через кнопку «+ записать» (канал `registry`).
- **Экстренные пациенты?** Описание экстренного состояния в чате → сразу 103/112. На экране подтверждения записи есть предупреждение не вставать в очередь при неотложном состоянии.
- **Данные?** В демо всё вымышленное: клиника, врачи, «Демо-пациент XXXX». В очереди пациенту не показываются чужие имена. Регистратура видит только короткую метку, без медицинских данных.

## Ограничения (честно)

- Подключена только **вымышленная** демо-клиника. Реальные расписания требуют подключения клиники; записи в DMED нет.
- Голос проверен на имитации VoiceLab, построенной по формату их официального клиента. **С настоящим ключом не проверялся** — первым делом проверьте его на месте.
- Лимит запросов работает в памяти Worker; для продакшена нужен Rate Limiting API.
- Кабинет клиники только на русском.
- Нет офлайн-режима для клиники.
- Лист ожидания: удержание проверяется перед вставкой записи, а не уникальным индексом. В узком окне (миллисекунды между отменой и созданием предложения) обычная запись может успеть занять время — тогда пациент из листа возвращается на своё место, а не теряет его.
- Уведомление о предложении уходит только пациентам из Telegram; демо-пациенты в браузере видят его во вкладке «Талоны» (опрос каждые 5–15 с).
- Язык пациента не хранится, поэтому уведомление в Telegram приходит сразу на узбекском и русском.
- Прогноз — оценка `N·t + D`, не учитывает фактическую длительность приёмов.
- Медицинские данные реальных пациентов нельзя хранить на бесплатном зарубежном хостинге без проверки требований закона «О персональных данных».


## Медицинский сканер документов (новое)

В пациентском интерфейсе добавлена вкладка **«Сканер»**, доступная также из меню ☰.
Она принимает фотографию рецепта, назначения или лабораторного бланка и распознаёт
текст на русском, узбекском и английском языках с помощью Tesseract.js.

- OCR выполняется в браузере пользователя; исходное изображение не отправляется на API BepulMed.
- Языковые данные Tesseract загружаются при первом использовании, поэтому для первого OCR нужен интернет.
- В этой версии поддерживаются изображения, не PDF.
- Тип документа определяется только по текстовым ключевым словам и может быть ошибочным.
- Сканер не интерпретирует лабораторные показатели, не ставит диагнозы и не рекомендует лечение.
  Проверяйте распознанный текст по оригиналу и уточняйте медицинские решения у врача/фармацевта.
- Не загружайте документы других людей без их согласия. На общем устройстве нажмите «Очистить»
  и закройте вкладку после работы.
